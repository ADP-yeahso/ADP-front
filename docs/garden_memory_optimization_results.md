## 고정 에셋·데이터

감정별 후보 수는 분노 4 / 불안 4 / 죄책감 4 / 슬픔 4 / 애틋함 4 / 감사 4 / 중립 3이다. 코드의 `diary.id % urls.length` 규칙과 목록 순서를 비교 전후 유지한다.

| 시나리오 | 꽃 수 | 구성 | 목적 |
|---|---:|---|---|
| zero | 0 | 나무만 | 기본 WebView·renderer 비용 |
| mixed-30 | 30 | 운영 꽃 27종 전체 포함 | 일반 부하 |
| mixed-60 | 60 | 운영 꽃 27종 전체 포함 | 높은 부하 |
| heavy-60 | 60 | `Affection_Calendula.glb` 반복, affection 목록의 인덱스 2 | 높은 삼각형 부하 |
| month-switch | 30 / 60 | 페이지 인덱스 짝·홀에 따라 교체 | 빠른 월 이동·최신 세대 확인 |
| preview-27 | 27 | 카탈로그 모델 각 하나씩 | 전체 에셋 외형·로딩 확인 |
| real | 앱 일기 수 | AppData에 등록된 월별 일기 | 선택한 일기의 날짜·내용·상세 화면 연결 확인 |

`mixed-30/60`과 preview는 가상 ID를 사용하므로 일기 상세 연결 검증은 `real`에서 수행한다. 진단 배치 데이터는 사용자 일기로 저장하지 않는다. 운영상 60송이보다 큰 월이 가능하면 그 최대 규모도 추가한다.

현재 `Affection_Calendula.glb`는 60,144삼각형이며 예전 최적화 전 `Affection_Marigold.glb`와 파일 내용이 동일하다. 이 상태를 기준 에셋에 포함하며, 후속 에셋 교체는 코드 최적화와 구분한다.

## 진단 로그 읽는 방법 — 보완안 반영 후

공통 접두사는 `GARDEN_DIAGNOSTICS:`이며 `schemaVersion: 2`, `sessionId`, `generation`, `timestampMs`로 실행과 월 요청을 구분한다. 객체 자체는 기록하지 않는다.

| 필드 | 의미 |
|---|---|
| diaryCount | 현재 요청의 입력 일기 수 |
| mappedDiaryCount / skippedDiaryCount | URL로 분류한 일기 수 / 매핑하지 못한 일기 수 |
| sceneFlowerCount | scene에 연결된 논리적 꽃 인스턴스 수. 화면 픽셀에 보이는 수나 가려짐 여부는 아님 |
| pendingFlowerCount | 생성했으나 아직 scene에 연결하지 않은 꽃 인스턴스 수 |
| resources | scene과 대기 배치를 합쳐 중복 제거한 앱 소유 Mesh 자원 |
| sceneResources / pendingResources | scene / 대기 배치 각각의 자원. 공유 자원이 있을 수 있어 두 값을 단순 합산하지 않음 |
| logicalFlowers | 여러 mesh 파트에 공유된 일기 매핑을 중복 제거한 꽃 수 |
| instanceSlots | 파트별 인스턴스 합계. 꽃 송이 수와 다를 수 있음 |
| gardenLoadMs | JS가 유효한 일기 데이터를 받은 뒤 정원 준비까지의 시간. Flutter 시작·WebView 초기화 시간은 제외 |
| loading.active / waiting / peakActive | 세션의 실행 중·대기 모델 작업 수 / 세션 전체 최대 동시 작업 수 |
| renderer | 마지막 렌더 프레임의 geometry·texture·program 개수와 draw call·triangle 수. 전체 메모리 바이트는 아님 |
| activity | JS가 추적하는 리스너·타이머·RAF·카메라 tween. Flutter 타이머나 라이브러리 내부 자원 전체는 포함하지 않음 |

- 로딩 중 `flower_model_accepted` 로그에서 pending 자원이 증가하고, `garden_ready` 후 scene으로 옮겨가는지 확인한다.
- 준비 완료에서 mixed-30은 `diaryCount=30`, `mappedDiaryCount=30`, `skippedDiaryCount=0`, `sceneFlowerCount=30`, `pendingFlowerCount=0`이어야 한다. mixed-60은 각각 60/60/0/60/0이다.
- `invalid-emotion`은 입력 2 / 매핑 0 / 누락 2 / scene 꽃 0이 기대값이다. 이 실패 주입 값을 정상 데이터의 누락과 구분한다.
- 정상 탭 종료에서 `viewer_destroyed` 로그가 Flutter 터미널에도 도착하는지 확인한다. scene/pending 소유 자원, 대기 작업, canvas, 소유 이벤트·RAF·tween 정리를 점검한다.
- 종료 시 이미 실행 중인 취소 불가능 로딩은 잠시 남을 수 있다. `loading.active`의 즉시 0만을 합격 조건으로 삼지 않는다. 늦은 결과가 새 scene에 추가되지 않고 정리되는지, 실제 WebView 프로세스 메모리 추세를 함께 확인한다.
- GLTFLoader 내부의 진행 중 파싱·디코딩·이미지와 원본 GLTF의 짧은 생존 구간은 이 앱 소유 Mesh 집계만으로 완전히 관찰되지 않는다. 플랫폼 메모리 도구로 피크를 측정한다.
- 진단 켜짐 여부·로그량을 전후 동일하게 맞춘다. 실제 release 동작 확인에서는 진단 비활성 조건도 확인한다.

## 미측정·제약·보류 사항

1. 실기기 앱·WebView 메모리 피크/안정값, GPU 바이트, 프레임 지연·발열, 복귀 시간은 미측정.
2. `Neutral_foxtail.glb`의 선분 파트가 현재 Mesh 인스턴싱 경로에서 표시되지 않는다. 사용자가 확인한 털 표현 누락은 **후속 보완으로 보류**했다. 이 외형 상태 그대로 기준을 고정하며, 메시 재수출 또는 선 렌더링 지원을 적용하면 에셋/코드 조건이 달라지므로 다시 측정한다.
3. 일기 상세 카드의 공통 꽃 이미지·“꽃 이름”·“꽃말”은 고정 표시다. 실제 꽃 종류와의 연결은 별도 미완료 항목.
4. 홈 UI/카메라 배치를 추후 변경할 수 있다. 비교 실험 중에는 동일하게 고정하고, 최종 배치 후 10단계 검증을 다시 확인한다.
5. 08~09 후보는 실측 결과에 따라 각각 적용·보류·에셋 의존으로 기록한다. 이 기준과의 비교는 08~09의 추가 효과이며, 02~07 전체 효과를 입증한 수치가 아니다.
